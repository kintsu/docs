# ERR-0018: Form Metadata Error Domain

## Overview

This specification defines the KFM (Kintsu Form Metadata) error domain, covering all errors related to form attributes, format validation, and format chaining in Kintsu schema files. Form attributes specify canonical messaging formats for fields.

For type system rules, see [TSY-0015](/specs/tsy/tsy-0015). For compilation details, see [SPEC-0024](/specs/spec/spec-0024).

## Error Definitions

### KFM0001: MissingOpenParen

**Severity:** Error
**Phase:** Parsing

**Message:**

```
expected '(' after form attribute identifier
```

**Primary Span:** The form attribute

**Help:** Form attributes require parentheses: `#[form(format)]`

**Example:**

```
error[KFM0001]: expected '(' after form attribute identifier
  --> schema/types.ks:1:1
   |
 1 | #[form json]
   |       ^ expected '(' here
   |
   = help: use #[form(json)] instead
```

### KFM0004: MalformedChainSyntax

**Severity:** Error
**Phase:** Parsing

**Message:**

```
malformed format chain syntax
```

**Primary Span:** The malformed chain expression

**Help:** Format chains use `=` to separate stages: `#[form(base64 = gzip = json)]`

**Example:**

```
error[KFM0004]: malformed format chain syntax
  --> schema/api.ks:1:1
   |
 1 | #[form(base64, gzip, json)]
   |              ^ expected '=' for chaining, not ','
   |
   = help: use #[form(base64 = gzip = json)] for format chains
```

### KFM1001: UnknownFormatVariant

**Severity:** Error
**Phase:** Resolution

**Message:**

```
unknown format variant: '{name}'
```

**Primary Span:** The unknown format identifier

**Help:** Lists valid format variants for the field type.

**Example:**

```
error[KFM1001]: unknown format variant: 'rectangular'
  --> schema/math.ks:2:8
   |
 2 | #[form(rectangular, precision = f64)]
   |        ^^^^^^^^^^^ unknown format
   |
   = help: valid complex formats: cartesian, polar, tuple
```

### KFM2001: FormIncompatibleWithFieldType

**Severity:** Error
**Phase:** Validation

**Message:**

```
form '{format}' is not compatible with field type '{type}'
```

**Primary Span:** The form attribute

**Related Spans:** The field type annotation

**Help:** Explains which formats are valid for the field type.

**Example:**

```
error[KFM2001]: form 'polar' is not compatible with field type 'str'
  --> schema/types.ks:2:1
   |
 2 | #[form(polar, precision = f64)]
   | ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ polar is for complex numbers
 3 | name: str,
   |       --- field type is str
   |
   = help: polar format is only valid for complex fields
```

### KFM2004: ChainingCompatibilityViolation

**Severity:** Error
**Phase:** Validation

**Message:**

```
format chain incompatible: '{prev}' outputs {prev_category}, '{next}' requires {required_category}
```

**Primary Span:** The incompatible format in chain

**Related Spans:** The preceding format

**Help:** Explains category requirements for format chaining.

**Example:**

```
error[KFM2004]: format chain incompatible: 'json' outputs text, 'hex' requires binary
  --> schema/api.ks:1:8
   |
 1 | #[form(hex = json)]
   |        ^^^   ---- json outputs text
   |        |
   |        hex requires binary input
   |
   = help: use base64 for text-to-text encoding, or add compression: #[form(hex = gzip = json)]
```

### KFM2011: PolarFormRequiresFloatPrecision

**Severity:** Error
**Phase:** Validation

**Message:**

```
polar form requires float precision, got integer precision '{precision}'
```

**Primary Span:** The precision parameter

**Related Spans:** The polar format specifier

**Help:** Polar form represents angles which require float precision.

**Example:**

```
error[KFM2011]: polar form requires float precision, got integer precision 'i32'
  --> schema/math.ks:2:26
   |
 2 | #[form(polar, precision = i32)]
   |        -----              ^^^ integer precision not valid for polar
   |        |
   |        polar uses angle representation
   |
   = help: use f32 or f64 for polar form, or use cartesian for Gaussian integers
```

### KFM4001: MissingPrecisionParameter

**Severity:** Error
**Phase:** Validation

**Message:**

```
precision parameter required for '{format}' form on complex field
```

**Primary Span:** The form attribute

**Related Spans:** The field declaration

**Help:** Complex number formats require explicit precision specification.

**Example:**

```
error[KFM4001]: precision parameter required for 'polar' form on complex field
  --> schema/math.ks:2:1
   |
 2 | #[form(polar)]
   | ^^^^^^^^^^^^^^ missing precision parameter
 3 | angle: complex,
   |
   = help: specify precision: #[form(polar, precision = f64)]
```

### KFM4002: ComplexRequiresForm

**Severity:** Error
**Phase:** Validation

**Message:**

```
complex field requires explicit form attribute
```

**Primary Span:** The field declaration

**Help:** All complex fields must specify format and precision via form attribute.

**Example:**

```
error[KFM4002]: complex field requires explicit form attribute
  --> schema/math.ks:3:5
   |
 3 |     value: complex,
   |     ^^^^^^^^^^^^^^ bare complex not allowed
   |
   = help: add form attribute: #[form(cartesian, precision = f64)] value: complex
   = note: use namespace-level #![form(...)] to set defaults for multiple fields
```

### KFM4003: F8RequiresForm

**Severity:** Error
**Phase:** Validation

**Message:**

```
f8 field requires explicit form attribute specifying format variant
```

**Primary Span:** The field declaration

**Help:** All f8 fields must specify format variant (e4m3 or e5m2) via form attribute.

**Example:**

```
error[KFM4003]: f8 field requires explicit form attribute specifying format variant
  --> schema/ml.ks:3:5
   |
 3 |     weight: f8,
   |     ^^^^^^^^^^ bare f8 not allowed
   |
   = help: add form attribute: #[form(e4m3)] weight: f8
   = note: e4m3 provides higher precision (±448), e5m2 provides larger range (±57344)
```

### KFM2012: F8ValueOutOfRange

**Severity:** Error
**Phase:** Validation

**Message:**

```
f8 value {value} exceeds {variant} format range (±{max})
```

**Primary Span:** The value literal or expression

**Related Spans:** The form attribute declaring the format

**Help:** Explains the valid range for the declared f8 format variant.

**Example:**

```
error[KFM2012]: f8 value 500.0 exceeds e4m3 format range (±448)
  --> schema/ml.ks:5:14
   |
 3 | #[form(e4m3)]
   | ------------- format declared here
 ...
 5 |     weight = 500.0,
   |              ^^^^^ value out of range
   |
   = help: use e5m2 format for values up to ±57344, or reduce value to ±448
```

### KFM2013: InvalidF8FormatVariant

**Severity:** Error
**Phase:** Validation

**Message:**

```
unknown f8 format variant: '{variant}'
```

**Primary Span:** The form attribute

**Help:** Lists valid f8 format variants.

**Example:**

```
error[KFM2013]: unknown f8 format variant: 'e3m4'
  --> schema/ml.ks:2:8
   |
 2 | #[form(e3m4)]
   |        ^^^^ unknown variant
   |
   = help: valid f8 formats: e4m3 (precision, ±448) or e5m2 (range, ±57344)
```

### KFM8001: GlobalCompositionalDefault

**Severity:** Warning
**Phase:** Validation

**Message:**

```
global compositional default applies recursively to all fields in namespace
```

**Primary Span:** The inner form attribute

**Help:** Namespace-level compositional forms (with chaining) apply to all fields. Use `#[allow(global_compositional_default)]` to acknowledge.

**Example:**

```
warning[KFM8001]: global compositional default applies recursively to all fields in namespace
  --> schema/api.ks:2:5
   |
 2 |     #![form(base64 = gzip = json)]
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ applies to all fields in namespace
   |
   = help: use #[allow(global_compositional_default)] to acknowledge
```

**Suppressible:** Yes, via `#[allow(global_compositional_default)]`

When suppressed, transforms to KFM7001 with Info severity.

### KFM7001: GlobalCompositionalDefault (Suppressed)

**Severity:** Info
**Phase:** Validation

**Message:**

```
global compositional default applies recursively (suppressed)
```

**Primary Span:** The allow attribute

**Related Spans:** The form attribute

This is the suppressed form of KFM8001. Only shown with `--verbose`.

**Example:**

```
info[KFM7001]: global compositional default applies recursively (suppressed)
  --> schema/api.ks:2:5
   |
 2 |     #![allow(global_compositional_default)]
   |     #![form(base64 = gzip = json)]
   |     ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ applies to all fields in namespace
```

## Suppression Mechanism

Category 8 (Warning) errors in this domain can be suppressed using `#[allow(...)]` attributes.

**Error name derivation:** Convert PascalCase error name to snake_case:

| Error Name                 | Allow Attribute                          |
| -------------------------- | ---------------------------------------- |
| GlobalCompositionalDefault | `#[allow(global_compositional_default)]` |
| RedundantPrecision         | `#[allow(redundant_precision)]`          |
| DefaultFormExplicit        | `#[allow(default_form_explicit)]`        |

**Category transformation:**

When suppressed:

- Category 8 (Warning) becomes Category 7 (Suppressed)
- Severity changes from Warning to Info
- Diagnostic only shown with `--verbose` flag

See [ERR-0001](/specs/err/err-0001) for complete suppression rules.

## Design Principles

1. **Actionable messages**: Every error explains what went wrong and how to fix it
2. **Precise spans**: Errors point to the exact source location
3. **Related context**: Complex errors show related locations
4. **Suppressible warnings**: Non-fatal issues can be acknowledged

## Implications

### For Schema Authors

- Form attribute errors provide clear guidance for correction
- Suppressible warnings allow intentional design decisions
- Namespace-level forms are warned to prevent unintended recursion

### For Tooling

- Error codes are stable identifiers for filtering and documentation
- Suppressed diagnostics use distinct category (7) for tooling awareness
- Span information enables IDE quick-fix suggestions
