# SPEC-0023: Workspace Manifest Implementation

## Overview

This specification defines the compiler implementation for parsing, validating, and deriving virtual manifests from workspace configurations (`schema.toml` with `resolver` field) as specified in [RFC-0024](/specs/rfc/rfc-0024).

This specification extends [SPEC-0018](/specs/spec/spec-0018) (Package Manifest Implementation) by reusing and composing its core types rather than duplicating them.

## Motivation

Workspace support requires:

- Discriminating workspace manifests from package manifests at parse time
- Reusing existing package manifest types to ensure consistency
- Deriving virtual package manifests that conform to [RFC-0019](/specs/rfc/rfc-0019)
- Resolving workspace inheritance (`.workspace = true` syntax)
- Managing file configuration with inherit/extend/override semantics

The implementation must leverage Rust's type system to enforce invariants at compile time and avoid runtime type mismatches between workspace-derived manifests and standalone package manifests.

## Architecture

### Manifest Discrimination

The parser first reads the TOML to determine manifest type by checking for discriminator fields:

```rust
#[derive(Deserialize)]
#[serde(untagged)]
pub enum ManifestKind {
    Workspace(WorkspaceManifests),
    Package(PackageManifests),
}
```

The discriminator fields are mutually exclusive:

- `resolver = "v1"` indicates a workspace manifest
- `version = "v1"` indicates a package manifest

If both or neither are present, parsing fails with a clear error.

### Type Reuse Strategy

Workspace manifests reuse package manifest types through composition and generic wrappers. This ensures derived virtual manifests are type-compatible with standalone package manifests.

#### Shared Core Types

The following types from SPEC-0018 are reused directly without modification:

| Type               | Description                         | Usage in Workspace                      |
| ------------------ | ----------------------------------- | --------------------------------------- |
| `PathOrText`       | String or file path union           | Inheritable fields                      |
| `Author`           | Author with name and optional email | Workspace and member authors            |
| `Dependency`       | Dependency specification enum       | Member dependencies                     |
| `PathDependency`   | Local path dependency               | Member dependencies                     |
| `GitDependency`    | Git repository dependency           | Member dependencies                     |
| `RemoteDependency` | Registry dependency                 | Workspace and member dependencies       |
| `FileConfig`       | File exclusion patterns             | Workspace defaults and member overrides |

#### Inheritable Field Wrapper

Fields that support `.workspace = true` inheritance use a generic wrapper:

```rust
#[derive(Deserialize, Serialize, Clone)]
#[serde(untagged)]
pub enum Inheritable<T> {
    /// Inherit from workspace configuration
    Workspace { workspace: bool },
    /// Explicit value
    Value(T),
}

impl<T> Inheritable<T> {
    /// Resolve inheritance, returning the value or pulling from workspace
    pub fn resolve(self, workspace_value: Option<&T>) -> Result<Option<T>, InheritanceError>
    where
        T: Clone,
    {
        match self {
            Inheritable::Workspace { workspace: true } => {
                workspace_value.cloned().ok_or(InheritanceError::MissingWorkspaceField)
            }
            Inheritable::Workspace { workspace: false } => Ok(None),
            Inheritable::Value(v) => Ok(Some(v)),
        }
    }
}
```

This pattern ensures:

- Type safety: inheritance resolution returns the same type as direct values
- Serde compatibility: untagged enum deserializes both forms
- Validation: missing workspace fields fail at resolution time, not silently

#### File Configuration Inheritance

File configuration uses a three-mode inheritance pattern:

```rust
#[derive(Deserialize, Serialize, Clone)]
#[serde(untagged)]
pub enum FileConfigMode {
    /// Inherit workspace defaults exactly
    Workspace { workspace: bool },
    /// Extend workspace defaults with additional patterns
    Extend { extend: FileConfig },
    /// Override workspace defaults completely
    Override(FileConfig),
}

impl FileConfigMode {
    pub fn resolve(self, workspace_files: Option<&FileConfig>) -> FileConfig {
        match self {
            FileConfigMode::Workspace { workspace: true } => {
                workspace_files.cloned().unwrap_or_default()
            }
            FileConfigMode::Workspace { workspace: false } => FileConfig::default(),
            FileConfigMode::Extend { extend } => {
                let mut base = workspace_files.cloned().unwrap_or_default();
                base.exclude.extend(extend.exclude);
                base
            }
            FileConfigMode::Override(config) => config,
        }
    }
}
```

### Workspace Data Model

#### WorkspaceManifest

The root workspace structure:

```rust
#[derive(Deserialize, Serialize, Clone, Validate)]
pub struct WorkspaceManifest {
    pub workspace: WorkspaceMeta,

    #[serde(default)]
    pub members: BTreeMap<String, WorkspaceMember>,
}
```

#### WorkspaceMeta

Workspace-level configuration that can be inherited:

```rust
#[derive(Deserialize, Serialize, Clone, Validate)]
pub struct WorkspaceMeta {
    /// Display name for the workspace
    pub name: Option<String>,

    /// Workspace description (not inheritable)
    pub description: Option<String>,

    /// Inheritable version for members
    pub version: Option<VersionSerde>,

    /// Version requirement for inter-workspace dependencies
    #[serde(rename = "version-resolver")]
    pub version_resolver: Option<VersionReqSerde>,

    /// Inheritable fields
    pub readme: Option<PathOrText>,
    pub license: Option<String>,
    #[serde(rename = "license-text")]
    pub license_text: Option<PathOrText>,
    pub authors: Option<Vec<Author>>,
    pub keywords: Option<Vec<String>>,
    pub homepage: Option<String>,
    pub repository: Option<String>,

    /// Workspace-wide file configuration defaults
    pub files: Option<FileConfig>,

    /// Shared dependency constraints
    #[serde(default)]
    pub dependencies: NamedDependencies,
}
```

#### WorkspaceMember

Per-package configuration with inheritance support:

```rust
#[derive(Deserialize, Serialize, Clone, Validate)]
pub struct WorkspaceMember {
    pub package: WorkspacePackageMeta,

    #[serde(default)]
    pub dependencies: BTreeMap<String, WorkspaceDependency>,

    #[serde(default)]
    pub files: Option<FileConfigMode>,
}

#[derive(Deserialize, Serialize, Clone, Validate)]
pub struct WorkspacePackageMeta {
    /// Package name (required, not inheritable)
    #[validate(length(min = 2, max = 128), custom(function = "validate_name"))]
    pub name: String,

    /// Version (required, inheritable)

    /// Relative path to schema directory (default: ./{alias})
    pub path: Option<PathBuf>,

    /// Description (not inheritable)
    pub description: Option<PathOrText>,

    /// Inheritable fields
    pub license: Option<Inheritable<String>>,
    #[serde(rename = "license-text")]
    pub license_text: Option<Inheritable<PathOrText>>,
    pub readme: Option<Inheritable<PathOrText>>,
    pub authors: Option<Inheritable<Vec<Author>>>,
    pub keywords: Option<Inheritable<Vec<String>>>,
    pub homepage: Option<Inheritable<String>>,
    pub repository: Option<Inheritable<String>>,
}
```

#### WorkspaceDependency

Dependencies support workspace sibling references and shared constraint inheritance:

```rust
#[derive(Deserialize, Serialize, Clone)]
#[serde(untagged)]
pub enum WorkspaceDependency {
    /// Reference workspace sibling or inherit from workspace.dependencies
    Workspace(WorkspaceRef),
    /// Explicit dependency (same as package manifest)
    Explicit(Dependency),
}

#[derive(Deserialize, Serialize, Clone)]
pub struct WorkspaceRef {
    pub workspace: bool,
    /// Optional version override for compatibility checking
    pub version: Option<VersionReqSerde>,
}
```

### Virtual Manifest Derivation

The workspace parser derives virtual `PackageManifest` instances for each member. This is a compile-time operation that produces type-compatible manifests.

#### Derivation Algorithm

```rust
impl WorkspaceManifest {
    pub fn derive_member_manifest(
        &self,
        alias: &str,
        member: &WorkspaceMember,
    ) -> Result<PackageManifest, DerivationError> {
        let workspace = &self.workspace;

        // Resolve package metadata
        let package = PackageMeta {
            name: member.package.name.clone(),
            version: member.package.version.clone()
                .resolve(workspace.version.as_ref())?,
            description: member.package.description.clone(),
            license: member.package.license.clone()
                .and_then(|i| i.resolve(workspace.license.as_ref()).transpose())
                .transpose()?,
            license_text: member.package.license_text.clone()
                .and_then(|i| i.resolve(workspace.license_text.as_ref()).transpose())
                .transpose()?,
            readme: member.package.readme.clone()
                .and_then(|i| i.resolve(workspace.readme.as_ref()).transpose())
                .transpose()?,
            authors: member.package.authors.clone()
                .and_then(|i| i.resolve(workspace.authors.as_ref()).transpose())
                .transpose()?
                .unwrap_or_default(),
            keywords: member.package.keywords.clone()
                .and_then(|i| i.resolve(workspace.keywords.as_ref()).transpose())
                .transpose()?
                .unwrap_or_default(),
            homepage: member.package.homepage.clone()
                .and_then(|i| i.resolve(workspace.homepage.as_ref()).transpose())
                .transpose()?,
            repository: member.package.repository.clone()
                .and_then(|i| i.resolve(workspace.repository.as_ref()).transpose())
                .transpose()?,
        };

        // Resolve dependencies
        let dependencies = self.resolve_member_dependencies(alias, member)?;

        // Resolve file configuration
        let files = member.files.clone()
            .map(|f| f.resolve(workspace.files.as_ref()))
            .unwrap_or_default();

        Ok(PackageManifest { package, dependencies, files })
    }
}
```

#### Dependency Resolution

Workspace dependencies resolve through a precedence chain:

1. If dependency name matches a workspace member alias, resolve to local path with `version-resolver` constraint
2. If dependency name exists in `[workspace.dependencies]`, inherit that constraint
3. Otherwise, report error for unresolved workspace reference

```rust
impl WorkspaceManifest {
    fn resolve_member_dependencies(
        &self,
        member_alias: &str,
        member: &WorkspaceMember,
    ) -> Result<NamedDependencies, DerivationError> {
        let mut resolved = NamedDependencies::new();

        for (name, dep) in &member.dependencies {
            let resolved_dep = match dep {
                WorkspaceDependency::Workspace(ws_ref) if ws_ref.workspace => {
                    self.resolve_workspace_ref(member_alias, name, ws_ref)?
                }
                WorkspaceDependency::Workspace(_) => continue,
                WorkspaceDependency::Explicit(d) => d.clone(),
            };
            resolved.insert(name.clone(), resolved_dep);
        }

        Ok(resolved)
    }

    fn resolve_workspace_ref(
        &self,
        from_alias: &str,
        dep_name: &str,
        ws_ref: &WorkspaceRef,
    ) -> Result<Dependency, DerivationError> {
        // Check if it's a sibling reference
        if let Some(sibling) = self.members.get(dep_name) {
            let path = self.compute_relative_path(from_alias, dep_name, sibling);
            let version = ws_ref.version.clone()
                .or_else(|| self.workspace.version_resolver.clone())
                .or_else(|| sibling.package.version.as_value().cloned().map(Into::into));

            return Ok(match version {
                Some(v) => Dependency::PathWithRemote(PathWithRemote {
                    path: PathDependency { path },
                    remote: RemoteDependency {
                        name: None,
                        version: v,
                        registry: None,
                    },
                }),
                None => Dependency::Path(PathDependency { path }),
            });
        }

        // Check workspace.dependencies
        if let Some(shared_dep) = self.workspace.dependencies.get(dep_name) {
            return Ok(shared_dep.clone());
        }

        Err(DerivationError::UnresolvedWorkspaceRef {
            from: from_alias.to_string(),
            reference: dep_name.to_string(),
        })
    }
}
```

### Path Resolution

File-based fields (`readme`, `license-text` with `{ path = "..." }`) in workspace configuration resolve relative to the workspace root, not relative to member directories.

```rust
impl WorkspaceManifest {
    /// Resolve all file-based fields relative to workspace root
    pub fn resolve_paths<F: FileSystem>(
        &mut self,
        fs: &F,
        workspace_root: &Path,
    ) -> Result<()> {
        // Resolve workspace-level file fields
        if let Some(readme) = &mut self.workspace.readme {
            *readme = readme.resolve_relative_to(fs, workspace_root)?;
        }
        if let Some(license_text) = &mut self.workspace.license_text {
            *license_text = license_text.resolve_relative_to(fs, workspace_root)?;
        }

        // Member paths are relative to their own directories (computed later)
        Ok(())
    }
}
```

### Versioned Envelope

The workspace manifest uses the same versioned envelope pattern as package manifests:

```rust
#[derive(Deserialize, Serialize, Clone)]
#[serde(tag = "resolver", rename_all = "snake_case")]
pub enum WorkspaceManifests {
    V1(WorkspaceManifest),
}
```

This enables future workspace format evolution while maintaining backwards compatibility.

### Member Discovery

Members are discovered from TOML tables matching the pattern `[alias.package]`:

```rust
impl WorkspaceManifest {
    /// Parse workspace members from raw TOML
    pub fn parse_members(raw: &toml::Table) -> Result<BTreeMap<String, WorkspaceMember>> {
        let mut members = BTreeMap::new();

        for (key, value) in raw {
            // Skip reserved tables
            if key == "workspace" || key == "resolver" {
                continue;
            }

            if let Some(table) = value.as_table() {
                if table.contains_key("package") {
                    let member: WorkspaceMember = table.clone().try_into()?;
                    members.insert(key.clone(), member);
                }
            }
        }

        Ok(members)
    }
}
```

### Validation Requirements

#### At Parse Time

- TOML syntax must be valid
- `resolver` field must be present and known
- At least one `[alias.package]` definition must exist

#### During Deserialization

- Package names must pass validation (same rules as SPEC-0018)
- Version fields must be valid semver or `.workspace = true`
- URL fields must be parseable

#### During Derivation

- All `.workspace = true` references must resolve to existing workspace fields
- All workspace dependency references must resolve to siblings or `[workspace.dependencies]`
- Circular dependencies between members must be detected
- Member paths must not escape workspace root

### Error Handling

Workspace-specific errors extend the existing error taxonomy:

| Error                    | Condition                                                |
| ------------------------ | -------------------------------------------------------- |
| `MissingResolver`        | No `resolver` field in workspace manifest                |
| `NoMembersFound`         | No `[alias.package]` definitions                         |
| `MissingWorkspaceField`  | `.workspace = true` but field not in `[workspace]`       |
| `UnresolvedWorkspaceRef` | Dependency references non-existent sibling or shared dep |
| `CircularDependency`     | Members form a dependency cycle                          |
| `PathEscapesWorkspace`   | Member path like `../external`                           |
| `DuplicatePackageName`   | Two members with same `name` field                       |
| `DuplicateAlias`         | Two members using same alias                             |
| `InvalidFilesExtend`     | `[alias.files.extend]` without `[workspace.files]`       |

See [ERR-0015](/specs/err/err-0015) for detailed error definitions.

## Design Principles

### Type Safety Through Composition

Rather than defining parallel type hierarchies, workspace types compose package types:

- `Inheritable<T>` wraps any inheritable field type
- `WorkspaceDependency` wraps the existing `Dependency` enum
- Derived manifests are actual `PackageManifest` instances, not a parallel type

This ensures type-level guarantees that derived manifests are compatible with all package manifest operations.

### Avoid Direct TOML Access

After initial parsing, all manifest access goes through typed structures:

- No `toml::Value` access outside the parser
- All field access is statically typed
- Validation happens at deserialization boundaries

### Single Source of Truth

The workspace manifest is the only manifest file in a workspace. Virtual manifests are:

- Derived on demand during compilation
- Never written to disk
- Cached in memory for the compilation session

### Serde-Driven Parsing

All parsing uses serde attributes to define serialization format:

- `#[serde(untagged)]` for discriminated unions
- `#[serde(tag = "...")]` for versioned envelopes
- `#[serde(rename = "...")]` for TOML naming conventions (kebab-case)
- `#[serde(default)]` for optional fields with defaults

This keeps the TOML format specification in sync with the Rust type definitions.

## Implications

### Performance

- Workspace parsing is slightly more expensive due to member iteration
- Virtual manifest derivation adds per-member overhead
- Caching derived manifests avoids repeated derivation

### Memory

- Entire workspace manifest is held in memory
- Derived manifests may duplicate inherited values
- Consider reference-counted shared fields for large workspaces

### Extensibility

- New inheritable fields require adding to both `WorkspaceMeta` and `WorkspacePackageMeta`
- The `Inheritable<T>` wrapper makes this mechanical
- New workspace features can extend the v1 format without version bump
